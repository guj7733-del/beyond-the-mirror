# 02 模型替换说明（第 4 阶段）

本文说明怎样把测试模型换成研究者自己的角色，以及换完后怎样检查和调整。

## 模型要求

| 项目 | 要求 | 缺少时程序怎么处理 |
|---|---|---|
| 格式 | VRM 0.x 或 1.0 优先；也接受 .glb / .gltf | GLB 按骨骼名称猜测人形结构，见下文 |
| 人形骨骼 | 必需 head；推荐 neck、spine、chest、双臂 UpperArm / LowerArm / Hand | 缺 neck 时低头全部由 head 承担；缺手臂骨骼时手臂保持模型默认姿势 |
| 可选骨骼 | upperChest、肩膀、眼球、手指 | 分别跳过对应动作（上身分段前倾、肩膀下沉、视线、握拳 / 握手机） |
| 面部表情 | 最好有 52 个 ARKit 同名表情（Perfect Sync）；至少要有左右眨眼和张嘴（VRM 预设 blinkLeft / blinkRight / aa） | 缺 ARKit 表情时用 VRM 预设近似；预设也没有时该表情不动 |
| 材质名称 | 能看出皮肤、头发、衣服、眼睛（VRoid 的 `_SKIN` / `_HAIR` / `_CLOTH` / `_EYE` 后缀可自动识别） | 无法识别的材质按“其他”处理；黑眼圈贴片投射到所有面部网格 |
| 静止姿势 | T-pose 或 A-pose | 手臂姿势由目标方向反算，A-pose 也能用 |
| 授权 | 允许用于研究原型、修改和公开展示 | 程序会显示 VRM 内的授权字段，需要人工核对 |

## 替换步骤

1. 备份测试模型，例如把 `public/models/avatar.vrm` 移到 `public/models/samples/PS_Male.vrm`。
2. 把自己的模型命名为 `avatar.vrm`，放到 `public/models/`。如果是 .glb，命名为 `avatar.glb`，在 `public/models/models.json` 里加一行（见下文“模型列表”），再到面板下拉框里选中它，选择会被浏览器记住。
3. 在终端检查模型：

   ```bash
   npm run inspect-model -- public/models/avatar.vrm
   ```

   重点看三处：缺少哪些骨骼、ARKit 52 覆盖了几个、授权字段。
4. 刷新页面，打开“调试 → 模型检查”。这里除了骨骼和表情，还会列出运行时采用的降级方式，例如“模型不是 Perfect Sync，已启用预设表情回退”。“角色 Avatar”一栏下方也会显示提示条数。
5. 调构图：在“角色 Avatar”里调宽度、高度、缩放、上下平移和朝向，让头部、肩膀和双手都在画面内，头顶留出放符号的空间。
6. 对齐眼部效果：按 2 切到黑眼圈阶段、按 4 切到螺旋眼、按 5 切到 × 眼，在“贴片微调”里调黑眼圈上下 / 大小、眼部符号大小 / 上下、头顶符号高度 / 大小。参数按模型分别保存在当前浏览器。调好后点“导出模型配置”，把下载的 `avatar.config.json` 放到 `public/models/`，与模型同名同目录，换浏览器或换电脑也能生效。
7. 跑一遍验收：开摄像头，确认眨眼、张嘴、眉毛、转头都能驱动角色；按 0–5 看六个阶段是否明显不同；再用计时器完整跑一次。

不想覆盖文件时，可以在“角色 Avatar → 本地文件…”里选择模型试用。文件只在浏览器里读取，不会上传；这种方式加载的模型刷新后会恢复成默认模型。

## 模型配置文件

`public/models/<模型文件名>.config.json`（与模型同名，扩展名换成 `.config.json`）会在加载模型时自动读取：

```json
{
  "overlayTuning": {
    "darkCircleOffsetY": 0,
    "darkCircleScale": 1,
    "eyeSymbolScale": 1,
    "eyeSymbolOffsetY": 0,
    "symbolOffsetY": 0,
    "symbolScale": 1
  },
  "materialCategories": {
    "Material.001": "skin",
    "Material.002": "hair"
  }
}
```

`materialCategories` 用于手动指定材质分组，可选值为 skin、face（眉毛、睫毛、嘴等五官线条）、hair、cloth、eye、other。分组决定两件事：去饱和时用哪一组参数（皮肤会额外变苍白），以及黑眼圈贴片投射到哪些网格上（只投射到 skin）。材质名可以从“调试 → 模型检查 → 材质分组”或 `npm run inspect-model` 的输出里复制。

## 模型列表

`public/models/models.json` 决定面板下拉框里有哪些模型：

```json
[
  { "name": "avatar.vrm（默认）", "url": "models/avatar.vrm" },
  { "name": "PS_Female（测试模型）", "url": "models/samples/PS_Female.vrm" }
]
```

新模型放进 `public/models/` 后，在这里加一行即可在面板中切换，方便对比。

## 使用 GLB 时的注意事项

- 骨骼按名称识别，支持 Mixamo（`mixamorig:LeftArm`）、VRoid 导出（`J_Bip_L_UpperArm`）、VRM 风格（`LeftUpperArm`）和 Blender 常见写法（`upper_arm.L`、`UpperArm_L`）。识别不到 head 骨骼时会报错并提示改用 VRM。
- 朝向自动判断：眼睛骨骼在头部后方，或左臂在 -X 一侧时，模型会被整体旋转 180°。
- 表情来自 Morph Target（Blender 中叫 Shape Key）。名称与 ARKit 一致时直连；也识别 `blink`、`blinkLeft`、`viseme_aa`、`mouthOpen` 等常见写法。
- GLB 不带 VRM 授权字段，授权需要另外确认。

条件允许时，建议用 Blender 的 VRM Add-on 或 Unity 的 UniVRM 把模型导出成 VRM。骨骼和表情会写进文件，不必靠名称猜测。

## 版本 B 对模型的额外要求

版本 B 只画头部，换模型后需要多看三点：

- 头部和身体最好分成不同的网格，或者至少脸和头发的顶点主要绑在 head 骨骼及其子骨骼上。程序据此隐藏身体网格（头部顶点不到 5% 的网格）。整个角色只有一个网格时，程序只能靠下巴下方的裁切平面去掉身体，脖子的切口在低头、抬头时可能露出来。
- 下巴要能从正面测到。程序沿面部中线向下打射线找下巴，测不到时按比例估算，模型检查里会提示“没有测到下巴位置”。这时可以用“角色 Avatar → 上下偏移”手动对齐。
- 头发不要垂到下巴以下，否则会被裁切平面截断。

换完模型后，按 M 切到版本 B，开摄像头看头部是否盖住脸、下巴是否对齐，再用“头部大小”和上下 / 左右偏移微调。两个版本共用“贴片微调”的设置。如果角色本身画了眼镜，把“角色戴眼镜”关掉。

## 从设计图到可驱动的模型

需求文档第 14 节的判断仍然成立：效果图只能作建模参考。参考图里的角色接近 Q 版比例（大头、短身），常见做法有两种：

- 在 Blender 中按三视图建模，绑定人形骨骼，制作眨眼、张嘴、眉毛等 Shape Key，再用 VRM Add-on 导出 VRM。Shape Key 最好直接用 ARKit 的 52 个名称；工作量不够时，至少做 eyeBlinkLeft、eyeBlinkRight、jawOpen、mouthSmileLeft / Right、browDownLeft / Right、browInnerUp 这几个。
- 先在 VRoid Studio 里做出接近的角色，导出 VRM 后再修改。测试模型的作者在 README 中说明，这两个模型可以作为给其他 VRoid 模型制作或复制 BlendShape 的源数据。

需求文档也提醒过：直接替换整个头部网格后，原来的 BlendShape 通常会失效。改脸型、换发型时，尽量在原网格上修改，或者重新制作表情形状。

## 常见问题

角色背对镜头：VRM 不会出现这种情况（程序已处理 0.x / 1.0 的朝向差异）。GLB 的朝向判断依赖眼睛或手臂骨骼，两者都没有时可能判断错，请改用 VRM。

眼部效果偏离眼睛：先确认“调试 → 模型检查”中“眼部定位方式”。`eye-mesh` 表示按眼白网格定位，通常最准；`eye-bones` 表示按眼球骨骼定位；`estimated` 是按头部骨骼估算的，需要用“贴片微调”手动对齐。

黑眼圈不显示：通常是皮肤材质没有被识别成 skin。在模型检查的材质分组里找到脸部皮肤材质，用配置文件的 `materialCategories` 指定为 skin。

表情不动：在模型检查的“表情映射”里查看该通道是直连、回退还是缺失。缺失的通道需要在建模软件中补做对应的表情形状。

手指姿势别扭：手指朝哪个方向弯，由程序根据手指骨骼和手掌朝向自动测量；弯多少则在 `src/avatar/PoseDriver.ts` 的 `ARM_POSES` 里设定。可以在那里调整三个姿势（cheer / phone / slump）的 `curl`（手指弯曲角度，弧度）和各段方向向量。

版本 B 里露出了脖子或身体：说明有身体网格没有被识别出来（它的部分顶点绑在了 head 骨骼上）。“调试 → 模型检查”会显示版本 B 隐藏和保留了几个网格。在建模软件中把这部分顶点的权重改到 neck 骨骼，或把头部和身体拆成不同网格。
