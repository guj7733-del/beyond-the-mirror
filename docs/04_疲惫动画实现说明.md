# 04 疲惫动画实现说明

## 结构

疲惫状态只由实验计时器决定，不读取摄像头：

```
ExperimentClock（真实时间）→ 当前阶段（时间表或手动锁定）
  → FatigueController：把参数平滑过渡到该阶段的目标值
  → FatigueParams（34 个数值）分四路输出：
      表情  → compose.ts 与面捕叠加 → 模型表情
      贴片  → FatigueOverlays（黑眼圈、眼袋、螺旋眼、× 眼、额头竖线、头顶符号）
      调色  → MaterialGrader（注入 shader 的饱和度 / 苍白度 / 亮度）
      姿态  → PoseDriver（低头、歪头、前倾、塌肩、摇晃、呼吸、手臂姿势）
```

计时器（`src/fatigue/`）、面捕（`src/tracking/`）、模型（`src/avatar/`）之间只交换数据。换模型不用改疲惫参数，调疲惫参数也不会影响面捕。

计时器按 `performance.now()` 计算真实经过的时间。切换标签页、掉帧都不会让实验计时变慢。

Stage 0 另有 0.3 的微笑；Stage 5 有 0.65 的吐舌（模型有 tongueOut 时生效）。Stage 4 的眼皮下垂比 Stage 3 低，因为螺旋眼贴片盖住眼睛，眼睛本身半睁即可。

第一版的 Stage 0 是双拳在胸前，到 Stage 1 才举起手机。第二轮修改意见认为举手机的样子更好，所以从 Stage 0 起就举着手机。

版本 B（头部叠在脸上）只用到上表的表情、贴片、调色和符号部分。头部必须贴合用户的脸，所以低头、歪头、前倾、塌肩和手臂姿势都不使用，眩晕摇晃只保留 40%，见 [07 版本 B 头部叠脸说明](07_版本B头部叠脸说明.md)。

## 过渡

阶段变化时，所有参数按指数方式逼近新目标：计时触发的切换约 1.6 秒到达 99%，手动切换和拖动时间轴约 0.3 秒。两者都可以在面板里调，手动切换设为 0 即硬切。“Reset Experiment”和导出六阶段立绘时直接跳到目标值，没有过渡。

## 叠加原则

需求文档要求疲惫动画不能完全覆盖用户实时的眨眼、张嘴。本项目的做法是让疲惫层只设定下限或偏移，用户的面捕值在剩余区间里继续起作用（`src/core/compose.ts`）。

| 通道 | 公式 |
|---|---|
| 眨眼 | 最终 = 下垂 + (1 − 下垂) × 用户眨眼 |
| 张嘴 | 最终 = 微张 + (1 − 微张) × 用户张嘴 |
| 睁大眼 | 最终 = 用户睁大眼 × (1 − 压制) |
| 眉毛下压、眉头上扬、嘴角下垂、吐舌 | 最终 = min(1, 用户值 + 疲惫值) |
| 微笑 | 最终 = min(1, 用户微笑 × (1 − 压制) + 疲惫微笑) |
| 头部 | 面捕旋转之上再叠加低头、歪头、摇晃 |

以 Stage 3 为例，眼皮下垂 0.56，用户睁眼时角色眼睛半闭，用户一眨眼角色就完全闭上。下表是用一段说话视频当摄像头实测的各阶段最终眨眼值和张嘴值范围：

| 阶段 | 下垂下限 | 最终眨眼值范围 | 张嘴下限 | 最终张嘴值范围 |
|---|---|---|---|---|
| 0 | 0 | 0.00–0.98 | 0 | 0.01–0.29 |
| 1 | 0.28 | 0.28–0.98 | 0 | 0.02–0.46 |
| 2 | 0.42 | 0.42–0.97 | 0.20 | 0.20–0.45 |
| 3 | 0.56 | 0.56–0.96 | 0.12 | 0.13–0.39 |
| 4 | 0.30 | 0.30–0.96 | 0.30 | 0.30–0.51 |
| 5 | 0.96 | 0.96–1.00 | 0.32 | 0.33–0.64 |

Stage 4 和 Stage 5 的眼睛被螺旋眼、× 眼贴片盖住。为了让用户眨眼仍然看得出来，贴片会按用户本人的眨眼值纵向压扁，用户眨眼时螺旋或 × 被压成一条线。

## 各效果的实现方式

需求文档第 05 节给出了推荐的实现方式，下面是本项目的做法。

黑眼圈 / 眼袋：用透明贴花（DecalGeometry）投射到脸部皮肤网格上，挂在 head 骨骼下随头转动。模型加载完成、还没摆姿势时，程序先把蒙皮网格烘焙成世界坐标，再从正前方打射线确定眼睛和眼下皮肤的位置。眼睛位置的确定顺序是：眼白网格的包围盒，其次是眼球骨骼，最后按 head 骨骼估算。贴花图案是程序画的紫褐色月牙形渐变（眼下阴影）和两道下弯弧线（眼袋）。

去饱和、失去红润：在每个材质的片元着色器末尾插入一个调色函数，先按亮度向灰色混合（饱和度），再向偏冷的灰色混合（苍白度），最后乘亮度。材质按名称分成皮肤、五官线条、头发、衣服、眼睛、其他六组，每组共用一套 uniform，每帧只改数值，不需要重新编译 shader。皮肤组额外使用苍白度，所以脸会比衣服先变灰；眼睛组还会随 irisDim 变暗。支持 three-vrm 的 MToon 和 three.js 内置材质，无法注入的材质会在模型检查里列出。

额头压力线、漫画符号：额头竖线是贴在额头前方的半透明平面（蓝紫色阴影加一排长短不一的细竖线，四周渐隐）。头部符号是始终面向镜头的精灵：精神线（Stage 0，轻微脉动）、叹气小云（Stage 3，从嘴边飘出后淡出）、旋涡（Stage 4，放倒在头顶上方旋转）、乌云和雨（Stage 5，雨丝向下滚动）。

眩晕眼、× 眼：眼睛前方的两个小平面，螺旋会旋转，两眼方向相反。

眼神失去光彩：模型有 `Fcl_EYE_Highlight_Hide` 这类“隐藏高光”Morph Target 时（VRoid 模型都有），程序把它注册为额外表情，按 highlightHide 逐级隐藏高光；没有时只靠眼睛材质变暗。

头部低垂：在面捕旋转之上叠加 neck / head 骨骼的俯仰和侧倾，低头量 neck 占 55%、head 占 45%。Stage 4 的摇晃是两个不同频率的正弦（侧倾 1.9 rad/s、俯仰 1.3 rad/s）。

肩膀下沉、身体塌陷：spine / chest / upperChest 分段前倾（38% / 34% / 28%），肩膀骨骼向下并向内扣。手臂有三个姿势，按阶段混合：

- phone：双手捧着手机，手机背面朝向镜头（Stage 0–4）
- slump：前臂横在身前，像趴在桌上（Stage 5）
- cheer：双拳在胸前（第一版 Stage 0 用过，现在保留为可选姿势；在 `stages.ts` 里把某一级的 `poseCheer` 设为 1、`posePhone` 设为 0 即可启用）

姿势用“目标方向”描述（上臂、前臂指向哪里，手指和掌心朝向哪里），程序根据模型静止姿势中实测的骨骼方向反算旋转，所以 T-pose、A-pose 和不同比例的模型都能用。手机是程序生成的圆角长方体，每帧放在两手之间，屏幕朝向角色眼睛，背面有摄像头模组，从镜头方向看到的是背面。

待机动作：呼吸（频率和幅度随阶段变化，Stage 5 最慢最深）；拿手机的阶段，右手拇指每隔约 2.6 秒滑一下屏幕；没有人脸时，头部缓慢微动并自动眨眼。头发等弹簧骨骼由 three-vrm 计算，会随头部和身体自然摆动。

## 自定义与调整

| 想改什么 | 改哪里 |
|---|---|
| 某一级效果的强弱、阶段的中英文名称和描述 | `src/fatigue/stages.ts` 的 `STAGES` |
| 各阶段默认时间 | 同上的 `defaultStartSec`；也可以直接在面板的 S0–S5 输入框里改 |
| 手臂三个姿势 | `src/avatar/PoseDriver.ts` 的 `ARM_POSES` |
| 用自己画的 PNG 替换符号 | 把透明 PNG 放进 `public/fatigue/`，在 `src/config/overlayTextures.ts` 里填写路径 |
| 贴片位置和大小 | 面板“贴片微调”，或模型配置文件，见 [02 模型替换说明](02_模型替换说明.md) |
| 调色公式 | `src/avatar/MaterialGrader.ts` 的 `GRADE_GLSL` |

`overlayTextures.ts` 可替换的图案有：darkCircle、eyeBag、spiralEye、xEye、foreheadLines、sparkle、sigh、swirl、cloud、rain。例如：

```ts
export const OVERLAY_TEXTURE_OVERRIDES = {
  cloud: 'fatigue/cloud.png',
  foreheadLines: 'fatigue/forehead_lines.png',
};
```

PNG 加载失败时自动退回程序绘制的默认图案，并在控制台给出提示。

## 已知限制

- 黑眼圈贴花随头部刚性移动，不跟随下眼睑的形变。眯眼幅度很大时，贴花边缘可能和眼睑略有错位。
- 测试模型的刘海盖住了额头，额头竖线画在刘海前面，效果接近漫画里画在头发上的阴影线。换成额头外露的角色后可以用“贴片微调”调整位置。
- 螺旋眼、× 眼的大小按眼白网格测量。眼睛形状特殊的模型可能需要手动调大小。
- Stage 5 眼皮下垂 0.96，眼睛基本闭合，用户眨眼只能通过 × 眼压扁来体现。
