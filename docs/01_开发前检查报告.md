# 01 开发前检查报告

需求文档第 13 节要求在编码前完成五项检查。项目目录里当时只有需求文档本身，没有角色模型，所以先按文档末尾截图推荐的来源下载了测试模型，对它做检查。本报告的检查结果可以用命令行随时复现：

```bash
npm run inspect-model                         # 默认检查 public/models/avatar.vrm
npm run inspect-model -- 某个模型.vrm --md     # 输出 Markdown
```

## 测试模型来源

需求文档截图中标为“最推荐的模型资产”的是 VRoid + 52 BlendShapes（GitHub：hinzka/52blendshapes-for-VRoid-face）。仓库提供男女两个 VRM：

| 文件 | 放在项目中的位置 | 大小 |
|---|---|---|
| VRoid_V110_Male_v1.1.3.vrm | `public/models/avatar.vrm`（默认模型） | 21.7 MB |
| VRoid_V110_Female_v1.1.3.vrm | `public/models/samples/PS_Female.vrm` | 22.2 MB |

截图中的另外两项没有采用：R3-3D 用两组关键词都没有检索到对应仓库，面捕链路直接基于 MediaPipe 官方 API 编写；Open Source Avatars（CC0）可以作为备选模型库，但其中模型大多只有 VRM 预设表情，缺少 52 个 ARKit 表情，正好对应本项目的“预设表情回退”路径（已用一个去掉 ARKit 表情的变体测试过，见 [05 验收记录](05_验收记录.md)）。

授权信息有一处不一致：仓库 README 写明个人和商业用途均可、允许再分发和出售、无需署名；但 VRM 文件内嵌的 meta 字段写的是 `licenseName: Redistribution_Prohibited`。本地研究和展示不受影响。如果将来把整个项目公开到 GitHub 等平台，建议把测试模型移出仓库，或在说明里引用 README 的授权原文。详见 [06 素材与授权](06_素材与授权.md)。

## 1. 模型文件格式

| 项目 | 男性模型（默认） | 女性模型 |
|---|---|---|
| 格式 | VRM 0.x（specVersion 0.0），GLB 容器 | 同左 |
| 导出工具 | UniVRM-0.79.0 | 同左 |
| 网格 | Face（9 个 primitive）、Body（8 个）、Hair（51 个） | Face、Body、Hair（56 个） |
| 材质 | 14 个，全部为 VRM/MToon | 14 个 |
| meta.title | PS_Male | PS_Female |

three-vrm 读取 VRM 0.x 时会把模型旋转 180°（`VRMUtils.rotateVRM0`），让 0.x 与 1.0 模型都面朝 +Z，后续代码按同一坐标约定处理。

## 2. Humanoid 骨骼与面部表情

两个模型都有 54 根人形骨骼。本项目用到的骨骼全部存在：

head、neck、spine、chest、upperChest、leftShoulder / rightShoulder、左右 UpperArm / LowerArm / Hand、leftEye / rightEye、全部手指骨骼。

视线类型为 Bone（用眼球骨骼转动）。

## 3. 已有的 Expression / Morph Target

VRM 表情（BlendShapeGroup）共 70 个：

- 17 个 VRM 预设：Neutral、A、I、U、E、O、Blink、Blink_L、Blink_R、Angry、Fun、Joy、Sorrow、LookUp、LookDown、LookLeft、LookRight；
- 52 个与 ARKit 同名的表情（BrowDownLeft … TongueOut），即 Perfect Sync；
- 1 个自定义的 Surprised。

Face 网格上的 Morph Target 共 122 个（女性模型 124 个），包括 VRoid 标准的 `Fcl_*` 系列（如 `Fcl_EYE_Close`、`Fcl_MTH_A`、`Fcl_EYE_Highlight_Hide`、`Fcl_EYE_Iris_Hide`）、52 个 ARKit 形状，以及作者加的 14 个辅助形状（如 `_eyeIrisMoveBack_L`）。其中 `Fcl_EYE_Highlight_Hide`（隐藏眼睛高光）不属于任何 VRM 表情，本项目在运行时把它注册成一个额外表情，用于疲惫阶段让眼神失去光彩。

three-vrm 读取 VRM 0.x 预设时会改用 VRM 1.0 的名称：A→aa、I→ih、U→ou、E→ee、O→oh、Joy→happy、Sorrow→sad、Fun→relaxed、Blink_L→blinkLeft、Blink_R→blinkRight；预设类型为 unknown 的表情保留原名（如 `BrowDownLeft`，首字母大写）。

## 4. MediaPipe 输出与模型表情的映射

MediaPipe Face Landmarker 每帧输出 52 个分类：`_neutral` 加 51 个 ARKit 名称（没有 tongueOut），另有 4×4 面部变换矩阵和 478 个关键点。两边的名称不一定一致，所以中间加了一层“ARKit 通道”：

1. 面捕结果写入 52 个 ARKit 通道，镜像模式下左右互换（MediaPipe 的 Left / Right 指被拍摄者自己的左右）；
2. 疲惫层在通道上叠加下限或偏移；
3. 每个通道按名称去模型里找表情，比较时忽略大小写和常见前缀（`BrowDownLeft`、`blendShape1.browDownLeft`、`ARKit_browDownLeft` 都能匹配）。找到就直连；找不到时按回退表用 VRM 预设近似（眨眼→blinkLeft / blinkRight，张嘴→aa，微笑→relaxed，皱眉→angry 等）；预设也没有的记为缺失并在调试面板列出。

测试模型 52 个通道全部直连。完整的映射表、回退公式、平滑参数见 [03 面捕映射说明](03_面捕映射说明.md)。

## 5. 还需要研究者补充的素材

| 素材 | 现状 | 用途 |
|---|---|---|
| 自己角色的可驱动 3D 模型（.vrm 优先） | 还没有。需求文档里只有六阶段效果图和构图参考图 | 第 4 阶段替换测试模型 |
| 角色正面 / 侧面 / 背面设计图 | 没有 | 建模时确认头部厚度、发型和服装结构 |

| 额头黑线、乌云、眩晕符号等透明 PNG（可选） | 程序已自带默认图案 | 想统一 Poster 画风时替换，方法见 [04 疲惫动画实现说明](04_疲惫动画实现说明.md) |
| 最终 Poster 的视觉规范（可选） | 没有 | 调整录屏背景、界面元素和导出尺寸 |

需求文档第 14 节已经指出：单张效果图不能直接变成可面捕的 3D 角色。参考图中的角色（棕色刺猬头、蓝色上衣、Q 版比例）需要先建模，并保留眨眼、张嘴等表情形状。建模和替换的要求见 [02 模型替换说明](02_模型替换说明.md)。在拿到模型之前，用测试模型就能完成全部功能验证。测试模型也缺失时，程序会换成一个按参考图配色的简易占位角色，流程仍能跑通。
