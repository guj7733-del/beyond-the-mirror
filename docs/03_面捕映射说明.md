# 03 面捕映射说明

本文说明 MediaPipe 的输出怎样变成角色的表情和头部动作，相关代码在 `src/tracking/`、`src/core/compose.ts` 和 `src/avatar/ExpressionBinding.ts`。

## 数据流

```
摄像头（getUserMedia，理想 1920×1080 / 30fps）
  → MediaPipe Face Landmarker（VIDEO 模式，numFaces = 1，GPU，失败时退回 CPU）
      输出：52 个 blendshape 分数、4×4 面部变换矩阵、478 个关键点
  → FaceProcessor：镜像互换 → 眨眼 / 张嘴重映射 → One Euro 平滑 → 头部姿态（含校准）
  → 52 个 ARKit 通道 + 头部 yaw / pitch / roll
  → compose.ts：与疲惫参数叠加
  → ExpressionBinding：通道 → 模型表情（直连 / 预设回退 / 缺失）
  → PoseDriver：头部姿态 → neck / head 骨骼
```

只在摄像头产生新帧时做检测（`requestVideoFrameCallback`），渲染仍按显示器刷新率进行。在测试电脑（Apple M1 Pro，Chrome 157，GPU 模式）上，面捕跟随摄像头帧率达到 30 fps，每帧检测 11–14 ms，渲染 60 fps。

## 镜像

MediaPipe 文档说明，`*Left` / `*Right` 指被拍摄者自己的左右，输入的是未镜像的画面。本项目默认打开镜像：屏幕上的摄像头画面左右翻转，像照镜子；角色也按镜子的方式反应，即用户闭左眼时，角色在屏幕同一侧的那只眼睛（角色自己的右眼）闭上。

实现方法是把所有成对的通道左右互换（`eyeBlinkLeft ↔ eyeBlinkRight`、`mouthLeft ↔ mouthRight`、`eyeLookInLeft ↔ eyeLookInRight` 等），并把头部的 yaw 和 roll 取反，pitch 不变。用转头测试视频验证过方向：视频中的人转向自己的左侧，镜像画面里他朝向屏幕左边，角色同样转向屏幕左边，yaw 达到上限 -55°。关闭“镜像”后，画面和角色都改为不翻转的对应关系。

## 重映射

| 通道 | 处理 | 默认值 | 面板中的调节项 |
|---|---|---|---|
| eyeBlinkLeft / Right | 线性映射：低于起点算睁眼，高于终点算闭眼 | 起点 0.12，终点 0.55 | 眨眼起点 / 眨眼终点 |
| 双眼同步 | 两眼差值小于 0.3 时取平均，减少单眼抖动；差值大时保留单眼眨眼 | 打开 | 双眼同步 |
| jawOpen | 乘以增益后截断到 1 | 1.3 | 张嘴增益 |
| 头部转动 | 乘以增益 | 1.0 | 头部增益 |
| 其余通道 | 原样使用 | | |

MediaPipe 的眨眼分数因人和光线而异，闭眼时常常到不了 1，所以要设一个映射区间。调试面板的“面捕”列显示映射后的值，调节时可以看着它闭眼、睁眼。

## 平滑

每个通道各用一个 One Euro Filter。它在静止时截止频率低，用来压住抖动；运动快时截止频率升高，减少延迟，所以眨眼不会被拖慢。面板的“平滑强度”（0–1，默认 0.5）同时调整两组参数：

| 对象 | 最小截止频率 minCutoff | 速度系数 beta | 默认（强度 0.5） |
|---|---|---|---|
| 52 个表情通道 | 4.0 Hz → 0.7 Hz | 2.0 → 0.6 | 2.35 Hz，1.3 |
| 头部角度（按度计算） | 2.5 Hz → 0.35 Hz | 0.08 → 0.025 | 1.43 Hz，0.053 |

单元测试检查了三点：恒定输入不被改变；交替抖动的方差降到原来的 20% 以下；阶跃输入在 10 帧（约 0.33 秒）内跟上 85% 以上。

## 头部姿态

1. 用 `Matrix4.fromArray` 读取面部变换矩阵，分解出旋转，按 YXZ 顺序转成欧拉角：yaw 绕竖直轴，pitch 低头为正，roll 歪头。
2. 镜像模式下 yaw、roll 取反。
3. 减去校准值。摄像头偏高或偏低时，用户正视屏幕也会被识别成低头或仰头；正对屏幕后点“校准正脸”（K），当前姿态即成为零点，校准值保存在浏览器中。
4. 限幅：yaw ±55°，pitch ±40°，roll ±40°。
5. 分配到骨骼：面捕旋转 35% 给 neck、65% 给 head；另把 12% 的 yaw 分给上身，转头时肩膀跟着轻微转动，看起来更自然。疲惫阶段的低头和歪头作为额外偏移叠加，见 [04 疲惫动画实现说明](04_疲惫动画实现说明.md)。版本 B 中头部要贴合用户的脸，面捕旋转全部给 head，不叠加低头和歪头。

版本 B 还用到五组关键点来摆放头部：双眼四个眼角（33、133、362、263）的平均点、下巴（152）、额头（10）、脸部左右轮廓（234、454）。它们和表情通道一样经过 One Euro 平滑，用法见 [07 版本 B 头部叠脸说明](07_版本B头部叠脸说明.md)。

角色的视线：模型有 eyeLook* 系列表情时直接用表情；没有时改用 VRM LookAt，按 eyeLook* 分数折算成眼球左右 ±18°、上下 ±12°。

## 通道到模型表情

名称比较时统一转小写，去掉下划线和常见前缀，所以 `BrowDownLeft`、`browDownLeft`、`blendShape1.browDownLeft`、`ARKit_browDownLeft` 都会匹配到 browDownLeft 通道。

模型没有某个 ARKit 表情时，按下表用 VRM 预设近似。只有当规则用到的通道全部没有直连时，该规则才会启用。预设表情往往会牵动整张脸，所以权重取得偏保守。

| 预设表情（VRM 1.0 名称） | 取值 | 说明 |
|---|---|---|
| blinkLeft / blinkRight | eyeBlinkLeft / eyeBlinkRight | 单眼眨眼 |
| blink | 左右眨眼的平均 | 只有双眼眨眼表情时使用 |
| aa | jawOpen × (1 − 0.5 × mouthFunnel) | 张嘴 |
| oh | mouthFunnel × 1.2 − 0.1 | O 型嘴 |
| ou | mouthPucker × 1.1 − 0.15 | 嘟嘴 |
| ee | 左右 mouthStretch 平均 × 1.2 − 0.1 | 咧嘴 |
| relaxed | 左右 mouthSmile 平均 × 1.1 | 微笑（VRoid 的 Fun；Joy 会闭眼，所以不用） |
| sad | max(browInnerUp − 0.6 × 外侧抬眉, 嘴角下垂) × 0.8 | 沮丧眉 / 嘴角下垂 |
| angry | 左右 browDown 平均 × 0.55 | 皱眉（弱） |
| surprised | min(外侧抬眉, browInnerUp) × 0.8 + 睁大眼 × 0.3 | 抬眉 / 睁大眼 |

所有结果截断在 0–1。同一个预设被多条规则驱动时取最大值。

回退路径用测试模型去掉 52 个 ARKit 表情后的变体（只剩 17 个预设）测试过：直连 0 个、回退 22 个、缺失 30 个。缺失的主要是脸颊、鼻子、嘴唇细节等预设无法表达的动作，眨眼、张嘴、微笑、皱眉、视线仍然可用。

## 人脸丢失

连续 250 ms 没有检测到人脸时，“面捕可信度”开始按指数方式衰减到 0（时间常数约 0.4 秒）。角色平滑回到中性表情，头部改为缓慢的待机微动，并开始自动眨眼（每 2.2–5.7 秒一次）；疲惫阶段照常推进。丢失超过 1.5 秒后重置平滑滤波器，人脸重新出现时不会从旧值慢慢滑过来。版本 B 的头部随可信度一起淡出，露出用户自己的脸。

## 怎样检查映射是否正确

- 调试面板的实时表格有两列：“面捕”是平滑后的用户表情，“叠加疲惫后”是最终送给模型的值。
- 调试面板的“表情映射”列出 52 个通道各自是直连、回退还是缺失，以及对应的模型表情名。
- 浏览器控制台输入 `bm.debugState()` 可以看到当前全部通道、头部角度和 MediaPipe 原始分数。
- `npm run check:e2e -- --video 人脸视频.mjpeg` 会自动检查张嘴、眨眼和头部是否有输出。
